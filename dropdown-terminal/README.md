# Dropdown Terminal: терминал, который выезжает сверху

Расширение для GNOME Shell. Нажал **Super+Enter** — сверху экрана выехал терминал.
Нажал ещё раз — уехал обратно. Всё, что в нём запущено, продолжает работать.

Сделано 8–9 ноября 2026 на Ubuntu 24.04, GNOME Shell 46, Wayland.

Как себя ведёт:
- Свой терминал без рамки и заголовка, 70% ширины по центру и 45% высоты
  рабочей области, поверх остальных окон и на всех рабочих столах.
- Шрифт — как в профиле gnome-terminal по умолчанию (если там не системный
  шрифт), иначе системный моноширинный; меняется в настройках.
- Его нет в панели задач и Alt+Tab, мышкой его не достать: только Super+Enter.
  Auto Tiling его не тайлит (а с версии из PR #6 и рамку фокуса вокруг него не
  рисует).
- Super+Enter, когда терминал в фокусе, убирает его. Если он виден, но фокус на
  другом окне, нажатие выводит его вперёд. Нажал, пока он уезжает, — вернётся.
- Появляется на мониторе, где курсор мыши, и на текущем рабочем столе.
- **Что внутри — выбираешь в настройках:**
  - **tmux** (по умолчанию): сессия `dropdown` живёт, даже если окно закрыть
    (Alt+F4) — следующий Super+Enter вернёт всё как было. Пропадает при выходе из
    системы и после `exit`. Это отдельный сервер tmux (`tmux -L dropdown`) со
    своим конфигом, твой обычный tmux и `~/.tmux.conf` не затрагиваются.
  - **обычная оболочка**: закрыл окно или `exit` — всё внутри закрылось.

Внутри терминала:

| Клавиши | Действие |
|---|---|
| Ctrl+Shift+C / Ctrl+Shift+V | копировать / вставить |
| Ctrl+= / Ctrl+- / Ctrl+0 | крупнее / мельче / как было |
| Alt+F4 | закрыть окно (в режиме tmux сессия останется) |

В режиме tmux:
- колёсико листает вывод;
- выделил мышью и отпустил — текст уже в буфере обмена, вставляется
  Ctrl+V где угодно. Протяни до верхнего или нижнего края — tmux листает
  дальше, так копируется и то, что ушло за экран. Двойной щелчок — слово,
  тройной — строка;
- выделение с **Shift** — выделение самого терминала, только видимая часть,
  копировать Ctrl+Shift+C;
- вкладки — окна tmux: Ctrl+B C — новое, Ctrl+B N / P — следующее / предыдущее.

## Установка

```bash
cd ~/Projects/ExtensionsUbuntu/dropdown-terminal
./install.sh
```

Потом **выйди из системы и зайди снова**: под Wayland GNOME загружает новый код
расширения только при входе. Проверить:

```bash
gnome-extensions info dropdown-terminal@nurik.local   # State: ACTIVE
```

Нужны `gjs` и `gir1.2-vte-2.91` (в Ubuntu 24.04 стоят вместе с GNOME), для режима
tmux — `tmux` (`sudo apt install tmux`). Нет tmux — запускается обычная оболочка.

## Настройки

«Расширения» → Dropdown Terminal → шестерёнка, или
`gnome-extensions prefs dropdown-terminal@nurik.local`:
- что внутри: tmux или обычная оболочка (со следующего запуска терминала);
- ширина и высота в процентах экрана, непрозрачность фона, шрифт;
- прятать, когда фокус уходит на другое окно;
- клавиша (по умолчанию Super+Enter).

То же командами:

```bash
S="--schemadir $HOME/.local/share/gnome-shell/extensions/dropdown-terminal@nurik.local/schemas"
K=org.gnome.shell.extensions.dropdown-terminal

gsettings $S set $K session tmux          # или plain
gsettings $S set $K width 70              # % ширины
gsettings $S set $K height 45             # % высоты
gsettings $S set $K opacity 95            # % непрозрачности фона
gsettings $S set $K font 'Noto Mono 10'   # пусто — как в gnome-terminal
gsettings $S set $K hide-on-unfocus false
gsettings $S set $K toggle "['<Super>Return']"
```

## Выключить или удалить

```bash
gnome-extensions disable dropdown-terminal@nurik.local
rm -rf ~/.local/share/gnome-shell/extensions/dropdown-terminal@nurik.local
```

После выключения открытый терминал становится обычным окном. tmux-сессия живёт,
пока её не закрыть: `tmux -L dropdown kill-server`.

## Как устроено

```
dropdown-terminal/
├── README.md, install.sh
├── tests/
│   ├── e2e.sh                       проверка в headless GNOME Shell
│   └── win.py                       обычное окно для проверок фокуса
└── dropdown-terminal@nurik.local/
    ├── extension.js                 запуск, показ, прятанье, место на экране
    ├── terminal.js                  сам терминал: GTK3 + VTE, без рамки
    ├── fonts.js                     шрифт по умолчанию: из профиля gnome-terminal
    ├── tmux.conf                    конфиг tmux для режима tmux
    ├── copy.js                      из выделения tmux в буфер обмена
    ├── prefs.js                     окно настроек
    └── schemas/                     настройки
```

- **terminal.js** — маленькое приложение на GJS: окно GTK3 без рамки, в нём
  виджет VTE (движок gnome-terminal). Шрифт — моноширинный шрифт системы,
  палитра Catppuccin Mocha. Запускает tmux или оболочку, закрывается вместе с ними.
- **copy.js** — `copy-command` tmux: отдаёт выделенное терминалу по D-Bus
  (`org.nurik.DropdownTerminal.Clipboard`), а тот кладёт его в буфер обмена.
  `wl-copy` в GNOME для этого открывает своё окно, и его схватил бы тайлинг.
- **extension.js** запускает его через `Meta.WaylandClient`: так окно сразу
  известно как своё (`owns_window`), и его ещё до первого кадра убирают из
  панели задач и Alt+Tab (`hide_from_window_list`). Окна вне списка mutter не
  сворачивает, поэтому на время сворачивания окно на один вызов возвращается
  в список.
- Выезд и уезд — анимация `translation_y` актёра окна; эффект сворачивания
  GNOME при этом пропускается.
- Терминал хранится в переменных модуля: GNOME выключает и включает расширение,
  когда выключается расширение, включённое раньше (так бывает и при блокировке
  экрана), и после этого это тот же терминал на том же месте. Живы ли окно и
  процесс, проверяется на месте (`list_all_windows`, `get_identifier`), а не по
  сигналам: окно, закрывшееся пока расширение было выключено, не трогается.
- Сразу после запуска закрывается копия сокета, которую держал
  `Gio.SubprocessLauncher`: иначе после `exit` соединение жило дальше и мёртвое
  окно висело, пока сборщик мусора GJS не освободит лаунчер (а это ещё и
  закрывало окна внутри сборки мусора). Клиенты завершившихся терминалов
  держатся в памяти на всякий случай.
- Новое место окна на Wayland применяется со следующим кадром клиента, поэтому
  выезд начинается, только когда окно уже на месте (не дольше 300 мс).

## Проверка без выхода из системы

```bash
./tests/e2e.sh            # OK или FAIL с окнами
VERBOSE=1 ./tests/e2e.sh  # то же, со временем каждой проверки
```

Отдельный GNOME Shell без экрана с двумя мониторами. Тест жмёт Super+Enter
виртуальной клавиатурой и проверяет:
- терминал выезжает наверх по центру, 70% × 45%, без рамки, вне Alt+Tab;
- уезжает и возвращается, в том числе на другом столе и мониторе;
- выходит вперёд, если фокус на другом окне; `hide-on-unfocus` работает;
- в режиме tmux сессия переживает закрытие окна и снова подключается;
- выделение мышью в tmux с протяжкой за верхний край попадает в буфер обмена
  вместе с ушедшими за экран строками, новых окон при этом не появляется,
  и копирование работает и позже, после сборки мусора в терминале;
- в режиме обычной оболочки tmux не запускается;
- `exit` и в tmux, и в оболочке сразу закрывает окно, следующее нажатие
  запускает новый терминал;
- после выключения окно обычное, после включения и блокировки экрана — то же
  окно наверху, а на экране блокировки оно остаётся поверх и вне списка окон;
- терминал, закрытый во время уезда, при `hide-on-unfocus` и пока расширение
  выключено, не ломает ничего (раньше последнее роняло шелл);
- в логе шелла (до его остановки) нет `JS ERROR`, `CRITICAL` и предупреждений
  из файлов расширения.

Настоящую сессию тест не трогает: у него свои D-Bus, настройки, runtime-папка и
сервер tmux.
